# TKT-025 — Delegation plan pattern and approval gate

**Type:** Feature
**Status:** Done
**Epic:** [EPC-007](../epics/EPC-007.md)

Give the orchestrator an output shape that makes its intent reviewable before
anything is spawned, and reusable for reporting outcomes afterwards.

## Acceptance criteria

- [x] `templates/delegation-plan.md` exists, under 30 lines, with fill-in slots
- [x] Plan half names agent, task, skills and dependencies per worker
- [x] Worker count stated explicitly so the user can cut it
- [x] Outcomes half records accepted / re-delegated / failed per worker
- [x] Escalations have their own slot rather than being folded into the summary
- [x] Orchestrator rule gains a `can-invoke` edge and prose on when to escalate

## Why

Reusing `templates/orchestrator.md` — as the parallel branch did — puts the
wrong shape on the output. That template is a *routing* summary: shape, route,
workflow, pre-flight. A delegation plan needs per-worker rows and an outcome
column, and none of those slots exist in it.

The approval gate is the user's only lever on cost. Delegation multiplies token
spend by the worker count, and a wrong split is discovered only once every
worker has finished paying for it.
