# TKT-023 — Developer agent definition

**Type:** Feature
**Status:** Done
**Epic:** [EPC-007](../epics/EPC-007.md)

Add the general-purpose implementer the kit was missing. The four existing
agents are all specialists that read and report; none of them writes code.

## Acceptance criteria

- [x] `resources/agents/developer.md` exists and parses
- [x] Constraints forbid spawning subagents
- [x] Constraints forbid editing outside the assigned part
- [x] `/verify` declared as a required edge, so done means built and tested
- [x] Self-check asks whether scope was quietly reduced

## Why

In the single-agent model the IDE agent is the developer, so no definition was
needed. The orchestrator spawns agents *by name*, and cannot spawn "the IDE
agent" — so an explicit implementer had to exist before delegation could work.

The anti-spawn constraint is the load-bearing part. A developer agent that can
delegate turns a two-level tree into an unbounded one, which exceeds the depth
every editor supports and produces work nobody is tracking.
