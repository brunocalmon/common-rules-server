# TKT-032: Implement `sync` vs `sync-offline` modes

## Description
Redesign the synchronization process in `common-rules-server` to support two modes:
1. `sync`: Lightweight mode. Installs hooks and the playbook (orchestration guidance) ONLY. Doesn't duplicate rules or skills locally, relying on the MCP server for context on demand.
2. `sync-offline`: Standalone mode. Exports all rules, skills, agents, workflows, and loops locally.

This aligns with the Pi.dev philosophy of keeping context tight unless operating fully offline.

## Acceptance Criteria
- [ ] `sync_service.py` supports `offline=True` vs `offline=False`
- [ ] `sync_to_ide` MCP tool takes an optional `offline` parameter (default `False`)
- [ ] In online mode, no rules, skills, workflows or loops are exported to the project
- [ ] In online mode, hooks and orchestration guidance are exported
- [ ] Existing `sync_to_ide` tests updated and passing
