# TKT-028 — Temporary runtime skills with user approval

**Type:** Feature
**Status:** Backlog
**Epic:** [EPC-007](../epics/EPC-007.md)

The full form of the user's idea: the orchestrator authors a complete skill at
runtime, the user approves it, and it exists for exactly one agent instance
before disappearing.

## Acceptance criteria

- [ ] Orchestrator can present a full composed skill for approval
- [ ] Approved skill reaches exactly one worker instance
- [ ] Skill leaves no trace on disk and does not enter the catalogue
- [ ] Refusing the skill leaves the delegation plan otherwise intact
- [ ] Acceptance scenario proving the skill is gone afterwards

## Why

This is the most speculative part of the architecture and the last thing that
should be built. It differs from [TKT-026](TKT-026.md) in degree: a composed
*instruction* is a paragraph in a prompt, a composed *skill* has a name, a
trigger, relationships and a report template — it looks like a resource in every
way except that it is not one.

That resemblance is the risk. A thing shaped exactly like a resource, invented
by an agent, approved in a hurry, and gone before anyone can review what it
did, is difficult to audit after the fact. The approval step is doing a lot of
work, and it will be approved by a user who has already approved a delegation
plan on the same screen.

Worth building only with evidence that composed instructions
([TKT-026](TKT-026.md)) were not enough.
