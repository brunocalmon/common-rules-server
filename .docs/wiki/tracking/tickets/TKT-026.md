# TKT-026 — Dynamic skill composition for subagents

**Type:** Feature
**Status:** Backlog
**Epic:** [EPC-007](../epics/EPC-007.md)

Let the orchestrator give a worker instructions that exist only for that worker
— a convention, a constraint, a house style particular to its part.

## Scope

The pattern is already stated in the orchestrator's instructions and requires no
server change: instructions live in the worker's prompt and die with it. This
ticket is about making it *reliable* rather than merely permitted.

## Acceptance criteria

- [ ] A documented shape for composed instructions, so workers parse them the same way
- [ ] Composed instructions surfaced in the delegation plan before approval
- [ ] Guidance on what belongs in a composed instruction versus a real resource
- [ ] Acceptance scenario exercising a worker that receives one

## Constraint found before starting

`templates/delegation-plan.md` is **exactly 30 lines** and
`test_templates_are_short_and_have_fill_in_slots` caps templates at 30. There is
zero headroom: the composed-instruction shape has to be expressed inside the
existing `{{DYNAMIC_INSTRUCTIONS}}` slot, not as new rows or a new section.

Found by the orchestrator agent while planning this ticket, not by its author.

## Why

Deferred out of the MVP deliberately. The value is real but it only matters once
delegation itself is in routine use, and the failure mode — a worker silently
receiving an instruction the user never saw — is better addressed after there is
evidence of how orchestration is actually used.

The line to hold: a composed instruction that keeps getting re-composed is a
resource that has not been written yet. `create_resource` is the answer then,
not a longer prompt.
