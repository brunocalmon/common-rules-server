# TKT-029 — Sync skills as native IDE commands

**Type:** Feature
**Status:** Done
**Epic:** [EPC-008](../epics/EPC-008.md)

Make every user-invocable resource typeable as a command in the editor, so
`/grill-me` works without a tool call to the server.

## Acceptance criteria

- [x] Claude export renders a `<chat-commands>` block in `CLAUDE.md`
- [x] Editors that do not read that block never receive it
- [x] Capability declared on `SyncTarget`, not tested by key at point of use
- [x] Command list built after the hook skip — an event-fired hook is never typed
- [x] Workflows and loops included despite carrying no `trigger` field
- [x] Ordering deterministic, so re-sync is byte-identical
- [x] `trigger: both` added so a command stays model-invokable

## Why

The gap the user hit directly: `/grill-me` failed because the skill existed only
in the MCP server. Sync exported it as a skill file but nothing told the editor
it was a command.

Two defects in the parallel branch's version were worth not copying:

**Filtering on `trigger` alone drops every workflow.** `trigger` is required of
skills only. `feature-dev`, `bug-fix`, `docs-gen` and `bdd-cycle` carry none, so
a trigger-only filter silently omits the four resources most obviously meant to
be typed. `_is_command()` treats workflows and loops as commands by kind.

**`trigger: user-invoked` severs model invocation.** `_write_skill` turns that
value into `disable-model-invocation: true`. Flipping `grill-me` to
`user-invoked` to get it listed would have broken the orchestrator rule's "Offer
/grill-me", `feature-dev`'s Discover phase, and `qa-engineer`'s required edge —
silently, because nothing asserts those edges still resolve after export. The
third trigger value `both` means listed *and* reachable.

## Verification

`uv run pytest src/test/service/test_sync_service.py` — includes a test that
`grill-me` appears in the command block while *not* carrying
`disable-model-invocation`, which is the regression that motivated `both`.
