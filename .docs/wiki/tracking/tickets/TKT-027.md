# TKT-027 — Workflow and loop delegation from the orchestrator

**Type:** Feature
**Status:** Backlog
**Epic:** [EPC-007](../epics/EPC-007.md)

Let the orchestrator hand a worker a whole workflow or loop rather than a single
task — a worker that runs `/feature-dev` end to end on its slice.

## Acceptance criteria

- [ ] A worker can be assigned a workflow, with its phase gates intact
- [ ] Phase gates that need user approval reach the user, not the orchestrator
- [ ] A loop assigned to a worker has a stated termination condition
- [ ] Delegation plan distinguishes task-workers from workflow-workers

## Why

Deferred because of an unresolved question about gates. A workflow's phase gate
means "stop and get a real answer from the user". A worker running a workflow
inside a delegation tree has no channel to the user — its parent is the
orchestrator.

Two candidate answers, neither settled:

- The orchestrator relays gates upward, becoming a proxy for the user. Cheap,
  but the user approves a phase they cannot see the context for.
- Workflow-workers are only assigned gate-free workflows, and anything with a
  gate stays with the primary agent. Honest, but narrow.

Settling this needs `/grill-me` before implementation, not during.

## Blocked on

The gate-relay question above. Do not start until it is answered.
