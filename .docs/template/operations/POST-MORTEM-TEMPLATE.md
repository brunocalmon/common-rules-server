> Post-mortems são blameless (sem culpados). Focamos em entender a falha do sistema e melhorar os processos.

## 1. Resumo do Incidente
O que aconteceu? (Parada total, corrupção de dados, lentidão).

## 2. Impacto no Usuário e Duração
Quantos usuários afetados, por quanto tempo.

## 3. Root Cause (A Causa Raiz)
Técnicamente, qual foi a falha originária (ex: 5-Whys).

## 4. Timeline
- 10:00 - Alerta disparado.
- 10:05 - Time identificou que o banco caiu.
- 10:25 - Backup restaurado.

## 5. Action Items (Lições Aprendidas)
O que faremos (código, alarme, infraestrutura) para que este problema específico nunca mais ocorra.
