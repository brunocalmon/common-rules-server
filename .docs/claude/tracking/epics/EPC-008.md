# EPC-008 — Native command invocation

**Status:** Done
**Roadmap:** [Roadmap](../ROADMAP.md)

## Outcome

Every user-invocable resource is typeable as a command in the editor. `/grill-me`
works because the editor knows the command, not because a tool call fetched it.

## Tickets

| Ticket | Title | Type | Status |
|---|---|---|---|
| [TKT-029](../tickets/TKT-029.md) | Sync skills as native IDE commands | Feature | Done |
| [TKT-030](../tickets/TKT-030.md) | Built-in and user resources compose | Feature | Done |

## Problem

The user typed `/grill-me` and it failed. The skill existed, sync had exported
it as a skill file, and nothing told the editor it was a command. The kit was
reachable only by paying a tool call for it — which is the cost sync exists to
remove.

## What changed

`SyncTarget` gained a `chat_commands` capability flag. Targets that declare it
receive a `<chat-commands>` list in their always-file; targets that do not,
never see one. The capability is declared in the target table rather than tested
by key at the point of use, so a fourth editor is a row, not a condition.

Two things the obvious implementation gets wrong:

**Filtering on `trigger` alone drops every workflow.** `trigger` is required of
skills only. The four workflows carry none, and they are the resources a user is
most likely to type. `_is_command()` admits workflows and loops by kind.

**`trigger: user-invoked` severs model invocation.** It becomes
`disable-model-invocation: true` on export. Marking `grill-me` user-invoked to
list it would have cut the orchestrator rule's "Offer /grill-me", `feature-dev`'s
Discover phase and `qa-engineer`'s required edge — silently. A third value,
`both`, means listed *and* reachable.
