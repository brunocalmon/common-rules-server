# EPC-008 — Native skill invocation

**Status:** Planned
**Roadmap:** [Roadmap](../ROADMAP.md)

## Outcome

Every skill, agent, workflow, loop, and hook in the kit is directly invocable
as a native IDE command (slash command, skill trigger, etc.) — not only through
the MCP server. The setup and sync processes register resources as native
commands so they work even when the server is unavailable.

## Problem

Today, skills like `/grill-me` exist only as MCP resources. Invoking them
requires a tool call to the server. When a user types `/grill-me` in the IDE,
the IDE does not recognise it as a command — it's not registered in the editor's
native skill/command system. The sync process exports rules, agents, and hooks
into native formats, but does not register skills as invocable commands.

## Key constraints

- Built-in resources work from scratch — no user configuration required
- User customisations (overrides, project resources) layer on top during
  setup and sync
- Each editor has its own mechanism: Cursor has skills in `.cursor/`, Claude
  Code has slash commands via CLAUDE.md or custom commands, Antigravity has
  its own skill format
- The sync must be mechanical (zero tokens) and idempotent

## Definition of done

- [ ] All tickets Done

      command on all three editors after sync
- [ ] User project resources are included alongside built-ins
- [ ] Re-syncing does not duplicate or corrupt existing native commands
