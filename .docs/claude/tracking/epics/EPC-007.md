# EPC-007 — Multi-agent orchestrator

**Status:** Planned
**Roadmap:** [Roadmap](../ROADMAP.md)
**ADR:** [ADR-007](../../architecture/adrs/ADR-007-multi-agent-orchestrator.md)

## Outcome

An orchestrator agent that the IDE spawns as a subagent with its own context
window, capable of analysing a request, proposing a delegation plan, and
spawning parallel worker agents (developer, reviewer, researcher, architect,
qa-engineer) that report back to the orchestrator — not the IDE.

## Grilling record

Interrogated on 2026-08-08. 10 questions, all recommendations confirmed.
Key decisions:

- Orchestrator rule and orchestrator agent coexist (lightweight vs heavy path)
- Orchestrator stays as `kind: agent`, not a new kind
- Design for exactly 2 levels: orchestrator + flat workers (no deeper chaining)
- Dynamic skills are prompt composition, not new API
- Delegation plan requires explicit user approval before spawning
- MCP server stays stateless — the orchestrator is a document, not a service
- Token governance is the editor's responsibility, not the orchestrator's
- MVP is definitions only — no dynamic skills, no automatic delegation
