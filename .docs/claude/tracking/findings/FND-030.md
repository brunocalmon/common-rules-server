# FND-030 — Clean left the command list pointing at deleted files

**Severity:** Medium
**Status:** Fixed
**Found by:** Running `sync_to_ide(clean=true)` and reading what survived

## What happened

`clean` removes generated files by looking for the generated header in them.
That works for everything it writes into `.cursor/`, `.claude/` and `.agents/`,
and hooks are uninstalled separately and correctly.

It never touched the always-file. After a clean, `CLAUDE.md` still carried the
managed block — four Always rules and a `<chat-commands>` list of 21 commands —
while every skill and agent file those commands resolve to had just been
deleted.

So the state after "clean" was worse than before it: the editor went on
offering `/grill-me`, `/feature-dev` and `/orchestrator`, and each one now
pointed at nothing.

## Why it was missed

The rule "generated files carry the generated header" is true of every file
`clean` was written to handle. The always-file is the one output that breaks it,
because it is not a generated file — the user owns `CLAUDE.md`, and only the
block inside it is ours. It is written through `managed_blocks.merge` precisely
so the surrounding content survives, which is exactly what makes it invisible to
a header scan.

The same asymmetry produced [FND-021](FND-021.md): the always-file is the place
where "ours" and "theirs" share a file, and it needs handling by name every time.

## Fix

`clean` now strips the managed block from each selected target's always-file. If
nothing of the user's remains, the file is removed; if anything does, the file
stays and only the block goes.

An always-file that never held our block is left alone and is not reported as
removed — a hand-written `CLAUDE.md` in a project that never synced must not be
deleted by a clean.

## Verification

Three tests in `test_sync_service.py`: the block is gone and the file removed
when it held nothing else; user prose around the block survives with the block
gone; an unrelated `CLAUDE.md` is untouched and unreported.

Confirmed end to end by cleaning this project, wiping every editor artefact, and
rebuilding through the local MCP server: `sync_to_ide()` with no argument
correctly refused ("No editor detected"), `setup_config(ide="claude")` restored
configuration and hooks, and `sync_to_ide()` then detected Claude Code alone —
31 files, 21 commands, no `.cursor/` or `.agents/`.
