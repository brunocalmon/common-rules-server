# FND-029 — A stop hook re-fired its reminder on every turn end

**Severity:** High
**Status:** Fixed
**Found by:** The user, after it fired eight consecutive times

## What happened

`hooks/completion-gate` was a `stop` hook whose script set a `message`:

```sh
decision=allow
message="Before finishing: answer the self_check questions of every resource
you used, and state honestly what you did not do. End your reply with the
session receipt."
```

The editor delivers that message as additional context each time the agent
finishes a turn. The agent answers, the turn ends, the hook fires again with
the identical message — and again, and again. Eight turns in one session were
spent re-answering a checklist that had already been answered, each one
consuming the user's quota.

## Why it was wrong

A `stop` hook cannot observe whether the obligation was met. It has no view of
the response that just went out, so it cannot distinguish "the agent skipped
the receipt" from "the agent wrote a full receipt three turns running". It
fires on the event, not on the condition, so it can only ever nag
unconditionally.

The `stop_hook_active` guard does not help here. That flag is set when a stop
hook *blocks* and forces continuation; this one was non-blocking
(`decision=allow`), so the flag stayed false on every firing.

The obligation was already covered. `rules/session-receipt` and
`rules/self-review` are both `type: Always` — they are in `CLAUDE.md` and the
agent reads them once per session. The hook added no coverage, only repetition.

## Its own self-check asked the right question

```yaml
self_check:
  - Does this fire without creating a loop that prevents the turn ending?
```

And the body claimed:

> It does not block: a gate that refuses to let a turn end produces a loop, and
> a loop is worse than a missed checklist.

The author reasoned about *blocking* loops and concluded non-blocking was safe.
The failure mode was a *message* loop, which non-blocking does nothing to
prevent. The question was correct and the answer was wrong — which is worse
than not asking, because it retired the concern.

## Fix

The resource is deleted. Enforcement that cannot observe its own condition does
not belong in a hook; it belongs in an Always rule, where it is stated once.

`test_no_shipped_hook_fires_on_every_turn_end` fails any future `stop` hook
that emits a message.

The kit now ships 5 hooks rather than 6.

## Verification

`.claude/settings.json` no longer contains a `Stop` entry; the remaining events
are `PreToolUse`, `PostToolUse` and `SessionStart`. 840 tests pass.
