# FND-031 — Agents were advertised as commands the editor could not offer

**Severity:** High
**Status:** Fixed
**Found by:** The user, trying to type `/orchestrator` and getting nothing

## What happened

[EPC-008](../epics/EPC-008.md) added agents to the `<chat-commands>` list on the
reasoning that an agent the editor knows as a subagent type is useless if the
user has no way to ask for one. The list was written; nothing was written to
make the names typeable.

Claude Code keeps two separate namespaces:

| Directory | What it defines | Who invokes it |
|---|---|---|
| `.claude/agents/*.md` | a subagent **type** | the model, via the Agent tool |
| `.claude/commands/*.md` | a **slash command** | the user, by typing it |

The export wrote the first and never the second, so `- /orchestrator (subagent)`
appeared in `CLAUDE.md` describing a command that did not exist. The agents
themselves loaded correctly and were spawnable by the model throughout — which
is why this looked like a broken agent rather than a missing command.

It worked in Antigravity for a reason that hid the bug: that target has no
`agents_dir`, so agents are exported **as skills**, and skills there are
invocable. The same catalogue produced a working command on one editor and a
dead one on another.

## Why it survived the tests

`test_every_advertised_agent_command_exists` did not exist. The tests asserted
the chat-commands block *contained* `- /orchestrator`, which it did. Nothing
asserted the editor could act on it.

That is the same shape as [FND-019](FND-019.md) and [FND-025](FND-025.md):
an exported resource naming something the export does not carry. The catalogue
was right, the block was right, and the artefact was inert — this project's
recurring failure.

## Fix

`SyncTarget` gains `commands_dir`. For a target that declares one, every agent
now also produces a command file whose body spawns the subagent of the same
name via the Agent tool, passing `$ARGUMENTS` as its task. Targets without one
are unaffected.

`clean` scans `commands_dir` too, so the files do not outlive the export.

The command body tells the agent it cannot see the calling conversation. A
subagent starts cold, and a command that forwards only the user's words without
saying so produces a worker guessing at context.

## Verification

Five tests in `test_sync_service.py`, including one that walks the advertised
command list and asserts a command file exists for every agent in it — so the
block and the directory cannot disagree again.

Confirmed on disk: `.claude/commands/` holds six files; `orchestrator.md`
carries `subagent_type: "orchestrator"` and `$ARGUMENTS`. Sync went from 31
files written to 37.
