# FND-028 — Agent tool restrictions did not survive the export

**Severity:** High
**Status:** Fixed
**Found in:** This implementation, during self-review of [TKT-024](../tickets/TKT-024.md)

## What happened

`_write_agent` emitted a `tools:` frontmatter line only for values matching
`[A-Z][A-Za-z]+`. Every agent in the kit names its tools in the kit's own
lowercase vocabulary — `read`, `grep`, `edit`, `execute` — so nothing matched
and the line was never written.

An exported agent with no `tools:` line inherits every tool the editor has.

## Why it mattered

I had just written the orchestrator agent with `tools: [read, grep, find,
spawn-agent]` and stated, in the commit message and in
[EPC-007](../epics/EPC-007.md), that it "holds no edit or execute so it cannot
implement instead of delegating".

That was true of the resource and false of the artefact. The exported
orchestrator had Edit and Bash available; the only thing standing between it and
implementing the work itself was a `constraints` line asking it not to.

The four pre-existing agents were affected the same way. `reviewer` declares
"Report only; never modify code" and exported with full write access.

## Root cause

The original code was deliberate — its comment reads "only pass through values
that look like them rather than guessing a translation." That was a reasonable
call while `tools` was descriptive. It stopped being reasonable the moment a
constraint was justified by it.

The fix is to supply the translation the comment declined to guess:
`NATIVE_TOOL_NAMES` maps the kit vocabulary onto each editor's names, collapses
duplicates (`execute` and `git-diff` both become `Bash`), and drops unmapped
server capabilities rather than emitting a value the editor would reject.

## Same shape as before

This is the fourth instance of the pattern this project keeps finding:
[FND-001](FND-001.md) placeholders, [FND-017](FND-017.md) hook escaping,
[FND-021](FND-021.md) block collision. Correct in the model, inert in the
artefact, and every test passing.

It was found the same way all of them were — by reading the generated file
instead of the resource that produced it.

## Verification

`test_every_agent_carries_a_tools_line_after_export` fails against the old
behaviour. Read from disk after a real sync:

| Agent | Exported tools |
|---|---|
| orchestrator | Read, Grep, Glob, Agent |
| developer | Read, Grep, Glob, Edit, Bash |
| reviewer | Read, Grep, Bash |

The orchestrator cannot edit. The developer cannot spawn.
